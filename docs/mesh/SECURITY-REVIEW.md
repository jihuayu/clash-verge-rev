# Focused safety review (2026-10-13)

- **Command injection:** the new status runner uses `tokio::process::Command` with fixed install paths and fixed `status --json --peers=false` arguments, null stdin and a timeout. It never invokes a shell. Provider input only enters serde-generated YAML. Interface/process/domain/CIDR values are validated; no configuration field becomes an executable path or CLI argument. Windows ProgramFiles supplies an OS installation root, not a frontend-supplied command. This does not protect against a locally compromised executable or environment.
- **Diagnostics:** only allowlisted backend state and whether an exit node is selected cross IPC. Deserialization ignores other JSON fields and peers are not requested. Raw stdout/stderr, auth URLs, tokens, identities and node keys are neither logged nor returned. A missing executable, parse error or timeout means unknown. No packet capture or remote probe happens in Preview.
- **Configuration rollback:** disabled/absent config returns the original mapping; each generation uses the source profile after ordinary enhancement, never the previously enhanced output. Existing entries remain in source. Core updates follow the existing checked-update/draft mechanism. Tests cover repeat generation, deduplication, disable and an error leaving the input untouched. This is configuration rollback, not OS snapshot restoration.
- **Interface failure:** direct adapter binding and stable desired rules prevent ordinary proxy-rule fallback; interface inventory cannot prove enrollment, route ownership or reachability. Names can be reused by another VPN. DNS/route ownership and live endpoint behavior require device tests. TUN-excluded and proxy-bypassing traffic follow OS routes and are not guaranteed fail-closed.
- **Mode/security boundaries:** Global/Direct are refused at app entry points; an independent external-controller client can bypass the app-level guard. Exit-node detection is point-in-time, not continuous. No TLS/certificate checks, ACLs or native firewall settings are relaxed.
- **Isolated packaging:** `coexistence-test` uses a separate identity/data directory, disables service mutations and automatic DNS writes, forces generated TUN off, selects sidecar and suppresses update checks. Before explicit proxy opt-in it preserves an existing OS proxy during startup/exit. After opt-in, normal cleanup disables the test proxy; it does not restore another application's old configuration. The acceptance plan requires an exact private baseline snapshot and explicit restoration after the test process exits.
- **Signing:** an ad-hoc local signature supplies bundle integrity only, not Developer ID trust or notarization. No signing identity/account is created; no notarization upload is performed. Gatekeeper and the application's macOS location guard remain intact. Do not remove quarantine, disable security assessment, or use `--no-sign` to claim usability.

Current unresolved risks: no macOS live DNS/traffic test, no Windows execution, manual route declarations, manual reconnect/interface revalidation, no continuous kill switch, no automatic PTR/short-name/DoH handling. Tailscale installation/registration and live network changes remain separately gated.
