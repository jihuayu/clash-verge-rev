# macOS 最小真实验收方案（尚未执行）

本轮构建物是 `coexistence-test` 特性下的独立 arm64 测试应用。它使用独立的 bundle ID、配置/备份目录、URL scheme 和开发 IPC 通道，直接启动普通用户 sidecar；不会复用生产配置。测试包阻止服务安装/卸载/修复和 UI 开启 TUN，自动 DNS 设置/恢复函数不执行，不检查更新。原有 macOS 启动位置检查、签名验证和 Gatekeeper 均不绕过。正常发行构建不受这些测试专用限制影响。

系统代理是全机共享设置，独立配置目录并不能隔离它。测试包未主动开启代理时，启动/退出会保留现有代理；一旦用户开启测试代理，退出会关闭它，**不会自动恢复另一应用的旧值**。因此必须按下述顺序显式恢复已保存原值，不能把“关闭共存配置”描述为“恢复所有 OS 设置”。

## 先完成的只读检查

1. 在 Chrome 官方 `login.tailscale.com` 登录已有账号；不创建新账号、不生成注册令牌、不接受新增设备确认。登录和 MFA 由用户完成。
2. 仅记录账号/组织、是否已有当前设备、拟用设备名称、批准测试的一台 tailnet 设备及 TCP 端口。不要导出节点密钥、登录 URL、令牌或完整设备清单。
3. 本机官方客户端安装状态、后端状态、exit node、实际 native/物理接口和路由；现有 Clash 是否使用 TUN、服务、系统代理守卫。存在未知项即先澄清。
4. 用只读 OS 接口记录当前活动网络服务的 HTTP/HTTPS/SOCKS/PAC 启用状态、地址和端口、旁路列表、DNS、IPv4/IPv6 默认及 split 路由、网络服务顺序。快照仅放在本地权限 0600 的验收目录，不输出 PAC 内容/凭据，不写入 Git。

## 一次合并确认应明确的内容

账号/组织、设备名称、是否新注册和目的地/端口确定后，再请用户确认以下实际动作；缺少这些信息时不要先拿泛化批准：

- 若客户端不存在，从 Tailscale 官方 macOS 下载页安装独立客户端，允许必要的系统扩展/VPN 配置；若已存在则复用。不得删除已有客户端注册或替换别的 VPN。
- 若尚未加入，在指定 tailnet 注册指定 Mac，创建持久设备访问。初次连接必须审查客户端实际选项：不选择 exit node，不接受子网路由，不公布路由，不开 SSH，不改 ACL。优先保留现有 OS DNS（关闭客户端的 DNS 接管选项），仅通过测试核心把明确的 MagicDNS FQDN 发给 Quad100；若该客户端不能在连接前保证这些选项，停止并补充变更范围，不能先连接后猜测。
- 启动 `/Applications/Clash Verge Tailscale Test.app`（安装位置需经批准），其普通用户 `clash-verge` 主进程、WebKit 进程及 `verge-mihomo` sidecar。只读 `tailscale status --json --peers=false` 子进程可用于诊断。不开 root 服务、不安装驱动、不运行服务安装器。Tailscale 自身会创建 native 虚拟接口、tailnet 路由及控制/DERP 连接，这是入网动作的一部分。
- 第一阶段保持当前系统代理/TUN/DNS原状，使用显式 `curl --proxy http://127.0.0.1:17897` 验证测试核心。若当前 Clash TUN 已开启，必须先将停用该 TUN 及其 DNS/路由恢复作为此次批准的一部分；否则不继续。
- 第二阶段才暂时停用原 Clash 的系统代理/守卫，并将活动网络服务的 HTTP、HTTPS、SOCKS 代理指向 `127.0.0.1:17897`，使用 Chrome 访问批准的测试 URL。PAC 保持关闭，旁路条目保持原值或在批准时列出精确差异。测试结束退出测试应用后立即恢复原代理/PAC/旁路设置和原 Clash 状态。
- 如测试失败，注销此次新注册的 Mac并撤销对应新设备访问；若用户希望成功后保留注册，应在确认中明确。已有注册绝不删除。客户端新安装文件和系统扩展是否保留也需明确，不能把“断开”当成撤销持久访问。

## 允许目标与验收顺序

仅使用用户选定的一个 tailnet 主机/已批准子网服务和一个 TCP 端口，不扫描 tailnet，不向现有远端设备部署服务。若没有可访问的测试服务，停在配置验证，不能虚报网络验收。

1. 原生 Tailscale 到该服务：明确 IPv4、IPv6（若有）和完整 MagicDNS FQDN。用 TCP/HTTP结果判断；ping 不是充分验收依据。
2. 显式代理访问同一目标。核实 mihomo 连接记录使用 `VERGE-MESH-0`，未命中普通代理。日志只留目标别名、协议、结果，避免记录密钥/URL查询参数。
3. 公开对照目标 `https://example.com/`（或用户指定的等价无敏感测试站），验证走普通代理。若用户不允许使用现有订阅，可另配置一个获准的代理；不要把 `DIRECT` 冒充普通代理测试。
4. DNS 使用明确的 MagicDNS 后缀及 Quad100，检查 A/AAAA；必要时用获准的抓包方式证明没有把私有 FQDN 发送给公网解析器。抓包本身另列范围，仅测试目标与53端口，不抓其他应用。应用自带 DoH、短主机名和 PTR不包含在基础验收内。
5. 在批准窗口中断开/重新连接 Tailscale一次，检验失败方式和恢复；接口名变更应提示重新审查。断开时不删除保护配置，不承诺 OS 层阻断所有旁路流量。
6. 关闭共存设置，验证测试核心配置回到未增强的源配置；退出测试应用。确认测试进程和17897监听已停止，然后恢复完整 OS 快照并重新启用原 Clash。复查原代理、DNS、路由及原有业务可用性。

## 异常恢复

- 一旦上网异常、DNS异常、流量进入错误接口或影响其他项目，立即停止当前请求与测试。先禁用测试代理/守卫，退出测试应用并仅终止该包的残留进程；不得按进程名批量杀死原 Clash、Tailscale 或其他项目。
- 程序崩溃时，活动 OS 代理可能仍指向17897；使用系统网络设置或已批准的精确恢复命令还原快照，不能仅依赖程序退出钩子。
- 若此次新启用 Tailscale导致故障，断开该客户端，然后复查 native 路由/DNS已恢复；不删除系统路由或“重置全部网络”来猜修复。
- 停止测试包之后才恢复旧代理，否则旧值可能被测试包的退出清理再次清除。按基线值恢复，不把全部代理关掉当作恢复。
- 新设备访问如需撤销，只处理此次注册且经核实的单个设备。不执行全 tailnet 注销、密钥轮换或 ACL 修改。

## TUN 单独审批

当前隔离包明确禁止 TUN。TUN 验收须使用另行审阅的构建，并单独批准服务/权限、精确路由、DNS劫持、native传输进程匹配及断连防护变更。Windows还需单独检查 strict-route/WFP/DNS影响。没有 OS 级原子恢复和防泄漏验证前，不应称为“任意 VPN/TUN 安全共存”。
